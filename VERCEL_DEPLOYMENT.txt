UBER-STYLE RIDE-HAILING APP: VERCEL DEPLOYMENT GUIDE
====================================================

IMPORTANT HOSTING MODEL
-----------------------
Deploy the React/Vite frontend to Vercel. Deploy the Node.js + Express + Socket.io
backend to a long-running Node host such as Render, Railway, Fly.io, or Azure App
Service. Do not deploy the Socket.io server as a Vercel serverless function: the
backend needs a persistent HTTP process for WebSocket connections and uploaded files.

1. DEPLOY THE BACKEND FIRST
---------------------------
Create a Web Service on your Node.js hosting provider.

Root directory: backend
Install command: npm install
Start command: npm start
Node version: 20 or newer

Add these backend environment variables in the provider dashboard:

NODE_ENV=production
PORT=<use the port supplied by the hosting provider, when required>
MONGODB_URI=<MongoDB Atlas connection string>
JWT_SECRET=<long random secret>
MAPBOX_API=<server-side Mapbox token>
CLIENT_ORIGIN=https://<your-vercel-project>.vercel.app
PUBLIC_API_URL=https://<your-backend-domain>
RIDE_REQUEST_RADIUS_KM=5

CLIENT_ORIGIN may contain multiple comma-separated HTTPS frontend origins, with no
trailing slash, for example:
https://your-app.vercel.app,https://www.your-domain.com

After deployment, check:
https://<your-backend-domain>/
It should return the application health response. The backend must be HTTPS so
Socket.io and production cookies work from the Vercel HTTPS site.

2. DEPLOY THE FRONTEND TO VERCEL
--------------------------------
Import the repository into Vercel and set:

Root Directory: frontend
Framework Preset: Vite
Build Command: npm run build
Output Directory: dist
Install Command: npm install

Add these Vercel environment variables for Preview and Production:

VITE_BASE_URL=https://<your-backend-domain>
VITE_MAPBOX_TOKEN=<URL-restricted public Mapbox browser token>

VITE_* values are public and are bundled into browser JavaScript. Never put
MONGODB_URI, JWT_SECRET, or MAPBOX_API in Vercel frontend variables.

3. FINISH CORS CONFIGURATION
----------------------------
Copy the final Vercel Production URL into the backend CLIENT_ORIGIN value.
If the Vercel URL changes, update CLIENT_ORIGIN and restart/redeploy the backend.
Use the exact origin only: https://example.vercel.app, without a path or trailing slash.

Socket.io uses the same CLIENT_ORIGIN value as HTTP API CORS. The browser must call
the backend over HTTPS, and the backend must allow credentials.

4. MONGODB ATLAS
----------------
In MongoDB Atlas Network Access, allow the backend provider's outbound IP ranges,
or use the provider's documented network access option. Create a least-privilege
database user and use its connection string in MONGODB_URI.

5. MAPBOX
---------
Use one server token in MAPBOX_API for geocoding/routing. Use a separate browser
token in VITE_MAPBOX_TOKEN and restrict it to the Vercel domains and only the scopes
needed by the map. Rotate any token that was ever committed or shared.

6. RELEASE CHECKS
-----------------
From the repository root:

cd frontend
npm run build
npm run lint

cd ../backend
npm test

Then verify in the deployed site:
- user signup and login
- captain signup and login
- map rendering and location search
- Socket.io captain online status and ride updates
- profile image upload URL
- logout and protected routes

COMMON FAILURES
---------------
"CORS error": CLIENT_ORIGIN does not exactly match the Vercel origin.
"Network Error": VITE_BASE_URL is missing, has a typo, or is not HTTPS.
Socket does not connect: backend host does not support persistent WebSockets, or
the backend CLIENT_ORIGIN does not include the Vercel origin.
Map is blank: VITE_MAPBOX_TOKEN is missing, invalid, or domain-restricted incorrectly.
Auth fails after login: confirm the API URL is the backend URL and that the token
returned by login is stored by the browser.
