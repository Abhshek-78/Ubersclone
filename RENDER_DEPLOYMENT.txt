UBERS RENDER DEPLOYMENT
=======================

The repository includes render.yaml for the backend service. It deploys the
backend directory with these commands:

  Root directory: backend
  Build command:  npm install
  Start command:  npm start
  Health check:   /

The backend has no compile step, so `npm install` is the correct Render build
command. Do not use `npm` by itself.

1. Create the backend service
--------------------------------

1. Push the repository to GitHub.
2. In Render, choose New + -> Blueprint and select the repository.
3. Render will read render.yaml. If creating the service manually, use:
   - Runtime: Node
   - Root Directory: backend
   - Build Command: npm install
   - Start Command: npm start
4. Choose a supported Node version in Render if your account requires one.

2. Add backend environment variables
-------------------------------------

In the Render service, open Environment and add these values. Enter the real
values in Render only; do not commit or upload a local .env file.

  MONGODB_URI=<MongoDB Atlas connection string>
  JWT_SECRET=<long random production secret>
  MAPBOX_API=<Mapbox server access token>
  CLIENT_ORIGIN=https://<your-frontend-domain>
  PORT=10000
  RIDE_REQUEST_RADIUS_KM=5

Render supplies PORT automatically. The value above is also present in the
blueprint as a default; keep Render's assigned port if Render changes it.

3. Deploy the frontend
----------------------

Deploy the frontend directory as a separate Vercel project:

  Root Directory: frontend
  Install command: npm install
  Build command: npm run build
  Output directory: dist

Add these Vercel environment variables for Production:

  VITE_BASE_URL=https://<your-render-backend-domain>
  VITE_MAPBOX_TOKEN=<Mapbox public access token>

After the frontend domain is known, update the Render backend variable
CLIENT_ORIGIN to that exact HTTPS origin, without a trailing slash, then
redeploy the backend. The backend CORS and Socket.io CORS checks use this
value.

4. Local environment protection
--------------------------------

Keep backend/.env and frontend/.env local. They are ignored by Git, and this
deployment setup does not read or modify them. Use the .env.example files as
templates. Never paste database credentials or JWT secrets into source files,
render.yaml, or frontend variables. VITE_* values are bundled into browser
code, so only use the public Mapbox token there.

5. Verify the deployment
-------------------------

1. Open https://<your-render-backend-domain>/ and confirm the API responds.
2. Open the Vercel site and test user and captain login.
3. Check the browser Network tab for requests going to the Render HTTPS URL.
4. Check the browser console for successful Socket.io connection.
5. If CORS is rejected, compare CLIENT_ORIGIN with the exact Vercel origin.
6. If the backend fails to start, review Render Logs and confirm every required
   backend variable is present.
